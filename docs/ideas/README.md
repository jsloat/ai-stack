# Ideas

`docs/ideas/` is for speculative ideas, deferred concepts, and "maybe later" notes that are worth preserving without promoting them into the active feature backlog.

Use this directory when an idea is:

- interesting enough to keep
- not ready for implementation planning
- blocked on other repo work
- still uncertain on scope, value, or fit

Do not use this directory for:

- active implementation backlog
- phased delivery plans
- settled repo policy
- scratch notes or raw transcripts

Use `docs/features/` instead when work is ready for execution planning, phased checklists, and acceptance criteria that should drive implementation.

## File Naming

Idea files should use the same date-prefix convention as feature docs:

```text
YYYYMMDD-short-name.md
```

The date is when the idea was first captured in the repo.

## Suggested Structure

Each idea note should cover:

- summary
- why it is interesting
- fit with current repo scope
- prerequisites or dependencies
- reasons not to do it yet
- promotion signals
- promotion target
- source references

Keep the notes concise. The point is durable recall and triage, not full design commitment.

## Lifecycle

- keep the note here while the idea is speculative or deferred
- move it into `docs/features/` when it becomes active backlog
- archive or delete it if the idea is no longer useful
